# ZWSO Methodology v0.4 . Reconciled world-state and forecasting context

## Purpose

ZWSO v0.4 reconciles two valid ideas that had drifted apart:

1. the original ZWSO: one immutable weekly snapshot of the observable world state; and
2. v0.3: a context-conditioned question and decision corpus built from ZWSO context packets.

The weekly world-state snapshot is restored as the core product.

The v0.3 question-generation and context-elasticity machinery remains available as a downstream consumer. It does not redefine ZWSO and it must never be required for the weekly producer to succeed.

Historical v0.1, v0.2 and v0.3 methodology files and snapshots remain unchanged.

## Core production principle

One self-contained weekly production run:

~~~text
public sources + canonical public-data stores
        ↓
freeze cutoff
        ↓
research + structured synthesis
        ↓
GSV Supabase zwso.zeitgeist_snapshots
        ↓
zwso.context_packets
        ↓
GitHub snapshots/YYYY/YYYY-MM-DD.md
~~~

GSV Supabase is canonical operational state.

GitHub is the immutable public archive.

The original ZWSO Neon database is legacy and migration evidence only. It is not an independent production writer after v0.4 activation.

## Four state layers

### Fast state

High-velocity signals:

- news and major events
- war and conflict developments
- markets and financial conditions
- FX
- energy prices and supply disruptions
- shipping and logistics interruptions
- cyber incidents
- significant weather
- public attention and culture velocity

### Structural state

Slow-moving variables that shape how shocks propagate:

- globalisation and trade structure
- energy systems
- climate state
- armed-conflict intensity and military burden
- demographics, fertility, births, ageing and dependency
- migration and forced displacement
- poverty and inequality
- child mortality and human development
- employment, unemployment, participation and wages
- capital flows
- investment and project formation
- strategic state capital allocation
- private and public fundraising
- mergers and acquisitions
- credit and leverage
- patents, innovation and technology diffusion
- income and wealth distribution

This is the network-weather layer.

### Belief state

Observable external expectations:

- Metaculus crowd forecasts
- Kalshi market-implied probabilities and price paths
- IMF, OECD and other institutional forecasts
- other public forecast references where terms permit

Belief state is not ground truth.

### Outcome state

Observed resolution:

- official statistics
- realised market and FX reference rates
- resolved prediction-market events
- completed, cancelled or defaulted projects
- realised capital flows
- published demographic and health outcomes
- externally verified event resolution

Outcome state scores forecasts.

## Source catalog

The GSV source catalog is authoritative for:

- source identity
- source family
- sensing role
- access mode
- cadence
- geography
- rights class
- training use
- active state
- priority
- provenance notes

Prefer official or primary public datasets where possible. Commercial sources may enrich the system but must not become required infrastructure.

The registered public-data estate includes macro/labour, demographics, human development, trade/globalisation, conflict, energy/climate, capital formation, strategic capital allocation, innovation/patents, public attention and external forecast references.

## Structural regime vector

The weekly context packet should expose these minimum dimensions:

~~~text
globalisation
energy
climate
conflict
demographics
human_development
labour
financial_conditions
capital_flows
capital_formation
strategic_capital
capitalism_distribution
innovation
technology_ai
~~~

Each dimension should carry:

- current state
- direction
- confidence
- evidence references
- coverage or missingness note

Do not invent numerical precision when the evidence supports only a categorical state.

## Fast versus structural reality

A core v0.4 signal is divergence between fast and structural reality.

Examples:

- negative news while employment and output remain resilient
- strong equity markets while capital formation contracts
- high AI investment while public social licence deteriorates
- large infrastructure announcements with weak disbursement
- improving GDP with worsening fertility, poverty or child-survival signals
- lower conflict salience while military expenditure rises

These divergences may be more forecast-useful than one aggregate mood score.

## Capital allocation

Capital allocation is a first-class ZWSO domain.

### Private capital formation

Track:

- small raises
- crowdfunding
- venture and growth rounds
- large private raises
- IPOs and follow-ons
- debt issuance
- raise count
- disclosed value
- median and upper-tail deal size
- sector and geography mix

Official U.S. sources include SEC Form D, Form C and public-offering filings. Licensed sources such as Dealroom or Crunchbase are optional enrichment only.

### Corporate consolidation

Track:

- announced M&A
- completed M&A
- cancelled deals
- deal count
- deal-size distribution
- sector concentration

### Real projects

Track:

- infrastructure
- energy
- manufacturing
- data centres
- transport and logistics
- critical minerals
- defence and security
- housing and public works

### Strategic and state capital

Track major capital allocators separately, including:

- China and Belt and Road Initiative
- EU Global Gateway and EIB
- World Bank Group
- ADB
- AIIB
- Japan and JBIC
- Saudi PIF
- UAE and Mubadala
- EBRD
- other major sovereign or development allocators when evidence warrants

Project lifecycle must distinguish:

~~~text
announced
→ approved
→ financed
→ committed
→ disbursed
→ construction started
→ operating
→ completed / cancelled / defaulted
~~~

An announcement is not equivalent to deployed capital.

Comparisons between allocators must preserve differences in definitions. Mobilised private capital, construction contracts, commitments, AUM and actual disbursements are not interchangeable measures.

## FX block

Every weekly snapshot contains a compact FX section.

Core pairs should include at least:

- USD/PHP
- GBP/USD
- EUR/USD
- USD/JPY
- USD/CNY
- AUD/USD
- USD/CAD
- USD/CHF
- USD/SGD
- USD/INR
- USD/KRW
- USD/AED

Prefer authoritative sources such as BSP, BIS, ECB and relevant central banks.

For each supported pair preserve when available:

- reference rate at cutoff
- one-week change
- four-week change
- realised volatility or simple dispersion
- source
- observation timestamp
- revision or status caveat

Commercial execution rates may be retained as context but are not canonical resolution when an official reference exists.

## Dogfood forecasting-performance block

Every weekly snapshot contains a summary of the internal mini predictive market.

Canonical sources:

- pukot_core.paper_forecasts
- pukot_core.forecast_model_scorecard

Report separately by venue and model:

- total locked forecasts
- open forecasts
- resolved forecasts
- invalid or failed records
- mean Brier score
- calibration where available
- mean absolute edge
- cumulative paper P&L where defined
- first and last observation timestamps

Unresolved forecasts are neither successes nor failures.

Metaculus and Kalshi are external belief/reference surfaces.

The Pukot paper market is our own locked belief history.

Keep these three roles distinct.

## Forecasting use

ZWSO is a context plane, not a forecasting oracle.

For every forecast preserve:

- question
- information cutoff
- base forecast
- ZWSO context version and date
- external belief references
- model and strategy version
- locked probability
- resolution
- score

The forecasting lab should test:

~~~text
baseline
vs baseline + fast state
vs baseline + structural state
vs baseline + belief state
vs full ZWSO context
~~~

Evaluate out-of-sample:

- Brier score
- calibration
- discrimination
- regime performance
- forecast improvement per unit cost

If a ZWSO state family does not improve forecasting, reduce or remove its forecasting weight.

## Temporal integrity

For every source:

- preserve observation timestamp
- preserve release timestamp
- preserve revision or vintage when available
- never leak post-cutoff information into a locked forecast
- distinguish forecasts from realised observations
- distinguish revised statistics from the value known at forecast time

Vintage data is especially valuable because it supports what-was-knowable-then replay.

## v0.3 question and context pipeline

The v0.3 context-conditioned question system remains valid as a downstream experiment.

Its tables and workflows may consume immutable ZWSO context packets to test:

- context elasticity
- appropriate invariance
- regime robustness
- hindsight resistance
- human/model divergence

Rules:

- it must not block the weekly snapshot producer
- it must not rewrite the snapshot
- raw source text does not automatically become training data
- source rights remain authoritative
- question generation remains downstream of observed state

## Immutability

- historical snapshots are append-only
- methodology changes do not rewrite old snapshots
- locked forecasts remain immutable
- revised data changes future snapshots or is recorded as a revision
- GitHub snapshot files are immutable publication artifacts

## Cadence

Default public cadence:

Wednesday 08:00 Asia/Manila.

Underlying observations may update more frequently.

Pukot forecast locks may run at a different cadence.

The public ZWSO archive remains weekly.

## Publication contract

A weekly run succeeds only when:

1. the canonical GSV snapshot row is written and read back
2. the context packet is written and read back
3. the matching GitHub Markdown file is committed and read back

If any stage fails, report the exact partial state.

Do not claim publication without GitHub commit and readback.

Social publishing and newsletters are outside the core ZWSO contract.

## Minimalism

v0.4 expands the evidence model, not the infrastructure footprint.

Do not add:

- a dashboard merely because data exists
- a second database writer
- a crawler when an official API exists
- a taxonomy for every source
- model training on source text merely because it is public

The governing test remains:

> Does preserving this state improve longitudinal understanding or forecasting?

If not, stop collecting it.
